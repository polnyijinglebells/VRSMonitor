# Контроль приёмников Virtual Radar Server

Веб-панель для Windows Server: автоматически получает приёмники из VRS, показывает состояние, непрерывное время работы/простоя, считает сообщения, хранит события в SQLite и формирует суточный отчёт с 08:00 до 08:00.

## Быстрый запуск

1. Установите и включите официальный плагин **VRS WebAdmin**. В VRS создайте пользователя и отметьте его администратором в `Tools → Options → Web Server → Administrators`.
2. В `config.json` укажите `vrs_url`, `vrs_username` и `vrs_password`. Адрес обычно имеет вид `http://127.0.0.1:8080/VirtualRadar` или `http://127.0.0.1:8888/VirtualRadar`.
3. Запустите `start.bat`.
4. Откройте `http://IP-СЕРВЕРА:8090`.
5. Разрешите входящий TCP-порт 8090 в Windows Firewall только для нужной локальной сети.

Python 3.10+ обязателен. Сторонние пакеты не требуются.

## Работа 24/7

Запустите PowerShell от имени администратора и выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install-service.ps1
```

Скрипт создаёт задачу `VRSMonitor`, которая работает от SYSTEM, запускается вместе с Windows и автоматически перезапускается после сбоя.

## Как определяется состояние

Состояние и счётчик «Сообщений всего» получаются из VRS WebAdmin (`WebAdmin/Index/GetState`). Это те же `Connection`, `ConnDesc` и `Msgs`, которые VRS показывает в таблице «Состояние канала данных».

Зелёным считается только состояние VRS `Connected` (в русской локализации обычно «Установлено»). «Соединение», «Повторное подключение», «Ожидание» и другие состояния показываются как отключённые. Суточное число сообщений и скорость вычисляются по приросту накопительного счётчика VRS; первый снимок принимается за базовый.

Логин и пароль VRS сохраняются в локальном `config.json`. Общий и суточный счётчики сохраняются в SQLite. Закрытие браузера не влияет на данные; после остановки и повторного запуска VRS монитор продолжает общий и суточный подсчёт, даже если внутренний счётчик VRS начал заново с нуля.

## Уведомления

- Telegram: создайте бота через BotFather и внесите токен и Chat ID в настройках.
- Webhook: укажите HTTP(S) URL, на него придёт JSON при отключении и восстановлении.
- Браузер: нажмите «Уведомления». Они работают, пока страница открыта; для постоянных уведомлений используйте Telegram/webhook.

## Ежедневный отчёт по военным самолётам в Telegram

1. Создайте бота через `@BotFather` и скопируйте Bot Token.
2. Для канала добавьте бота администратором с правом публикации сообщений. Для личного чата сначала откройте бота и нажмите Start.
3. В настройках панели включите «Отправлять отчёт автоматически», укажите время, токен и получателя (например, `@polnyijinglebell5` или числовой Chat ID).
4. Сохраните настройки и нажмите «Отправить тестовый отчёт».

Если сервер находится за HTTPS-прокси или антивирусом и Telegram возвращает `CERTIFICATE_VERIFY_FAILED`, сначала установите корневой сертификат прокси в доверенное хранилище локального компьютера. Как крайний вариант можно включить «Разрешить самоподписанный сертификат Telegram». Этот режим отключает проверку сертификата только для Telegram-запросов и должен использоваться исключительно в доверенной сети: HTTPS-посредник сможет увидеть токен бота и отчёт.

Приложение сохраняет только борта, для которых VRS передал `Mil=true`. Отчёт формируется за последние полностью завершённые контрольные сутки 08:00–08:00 и отправляется по локальному времени Windows Server. Маршрут берётся из полей VRS `From`, `Stops` и `To`; если VRS его не знает, в отчёте будет указано «не указан VRS».

## Данные и отчёты

- База: `data/vrs_monitor.db`.
- Журнал: `data/vrs_monitor.log`.
- CSV открывается в Excel; «Печать / PDF» создаёт печатный отчёт браузером.
- Для резервной копии копируйте каталог `data` (лучше при остановленном приложении).

## Доступ

Для простой парольной защиты задайте системные переменные `RADAR_USER` и `RADAR_PASSWORD` для учётной записи, запускающей приложение, затем перезапустите задачу. При публикации в интернет используйте HTTPS reverse proxy; напрямую открывать порт панели в интернет не рекомендуется.
